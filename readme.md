# Kara David's Wish Note: QAT Toolkit

## Repository Overview

This Quality Assurance Testing (QAT) toolkit documents the functional testing of an AI-generated PHP web application. The source test case is also available in the file `textcase.txt`.

The repository contains three parts:

- **Part A:** This `readme.md` file, containing the test case for an AI-generated web application
- **Part B:** `webapp-generation-prompt.txt`, the AI prompt used to create the test web application
- **Part C:** `test-webapp.php`, the single-file PHP web application generated by AI

## Test Case Documentation

| Field | Details |
|---|---|
| **Test Case ID** | TC-DataEntry-001 |
| **Test Case Title** | Data Entry - Valid |
| **Description** | Functional testing of the Data Entry page with backend validation using MySQL queries |
| **Preconditions** | The Kara David Birthday Wishnote App is installed locally and the MySQL database is pre-populated for comparison. The Data Entry page is accessed in the latest Chrome or Firefox browser. |
| **Test Data** | Five (5) valid entries containing First Name, Last Name, Government Position, and Location, each within its maximum character limit |
| **Status** | **Failed**: the Location value is not saved to the database (step i) |

## Test Execution

| Step | Action | Expected Result | Actual Result |
|---|---|---|---|
| a | Verify that the form contains labels in proper order and the text boxes are writable | The form contains labels in this order: "Target's First Name", "Target's Last Name", "Target's Government Position", and "Target's Location"; all text boxes are writable | The form contains labels in this order: "Target's First Name", "Target's Last Name", "Target's Government Position", and "Target's Location"; all text boxes are writable |
| b | Verify the "Send Wish Note" button | The "Send Wish Note" button changes color on hover and is not disabled | The "Send Wish Note" button changes color on hover and is not disabled |
| c | Enter test data on their respective fields | The respective fields accept data entries of valid test data | The respective fields accept data entries of valid test data |
| d | Click the "Send Wish Note" button; a modal will appear | A modal titled "Verify Target Data" appears at the center of the page | A modal titled "Verify Target Data" appeared at the center of the page. |
| e | Verify that the modal contains the same entry as the test data | The modal displays the same First Name, Last Name, Government Position, and Location as entered | The modal displayed the same First Name, Last Name, Government Position, and Location as the test data. |
| f | Click the Cancel button | The modal closes and the form retains the entered data without submitting | The modal closed and the form still contained the entered data; nothing was submitted. |
| g | Click "Send Wish Note" again, then click "Confirm and Send" in the modal | The modal closes, the form is submitted, and the page reloads | The modal closed, the form was submitted, and the page reloaded with an empty form. |
| h | Verify that a successful entry message shows on the Data Entry page | The message "Success! The wish note has been sent." is displayed above the form | The message "Success! The wish note has been sent." was displayed above the form. |
| i | Verify that the test data shows in the database | The `main_corrupt_politicians` table shows the new entry with the same values as the test data (query: `SELECT * FROM main_corrupt_politicians;`) | The table main_corrupt_politicians shows the new entry with First Name, Last Name, and Government Position, but the Location is empty/NULL. (query: `SELECT * FROM main_corrupt_politicians;`) |

## Setup Notes

1. Install and start the web server and MySQL/MariaDB (e.g. via Termux with `proot-distro` Ubuntu).
2. Place `test-webapp.php` in the web root (e.g. `/var/www/html/`) and open it through `localhost`.
3. Ensure the database `birthday_wishnote` and the table `main_corrupt_politicians` exist before testing.

> **Note:** Connecting as MySQL `root` without a password is acceptable for local development only. Always use a strong password in production.
